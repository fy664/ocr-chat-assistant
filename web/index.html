架构

一次读取，一次深读

没有常驻的采样循环。读取、OCR、图像压缩与模型请求都在后台线程完成；结果经 Schema 校验后才进入界面。

  1. 01

    粘贴或读取一次

    长聊天直接粘贴；也可以框选一次聊天窗口，只读取这一块，不会后台扫屏。

    粘贴mss 一次DPI 换算
  2. 02

    本地 OCR + 行结构

    PaddleOCR 识别后保留行结构，让「对方 / 我」的说话人标签不被压成一行。

    PP-OCRv6中文 / 英文CPU
  3. 03

    长文整理

    整理全文、截断过长部分，并把多张截图编码为压缩 JPEG，准备一次请求。

    30k 字4 张画面JPEG
  4. 04

    视觉 + 语义解读

    长文与画面一起交给模型：先找证据，再区分谜语、反话与试探，最后给回复。

    快速 / 深度视觉JSON 修复重试
  5. 05

    结果与回复

    Pydantic 校验通过后一次性上屏；回复建议只复制，不自动发送。

只有你点击「解读」时才会。言外不会持续监控，也不会后台扫屏；你手动读取的画面会压缩成 JPEG，和整段对话一起发送给你配置的模型服务商。视觉默认开启（因为表情包/贴纸是言外的核心），可在「设置 → 解读」里关闭；关闭后画面只在本地预览，不发任何图片。截图从不写入磁盘。

任何能显示在屏幕上的聊天窗口都可以框选，因为它只处理你框选区域里的像素，不读取应用内部数据。Discord / Telegram / 网页版聊天同样适用。小字体、深色模式或表情较多的界面可能影响 OCR 效果，可调整框选范围。

两个办法：把完整聊天记录直接粘贴进左侧编辑器（默认支持 30,000 字，可在设置里调）；或者向上滚动聊天记录，再点一次「读取画面」，程序会把新文字追加到已有内容里，并保留最多 4 张截图。长文不会因为一屏装不下就丢掉前文。

左侧就是可编辑的对话文本：OCR 读取后可以直接改，再点「解读」。建议保留「对方：」「我：」这样的说话人标签；如果 OCR 把行粘在一起，也可以手动换行。程序不会拿改过的文本去覆盖你的编辑。

深度模式会让推理模型展开更长的思考，实测约 30–60 秒；默认关闭。快速模式直接要求 3–5 条简短步骤和结论，本机实测约 25 秒。需要更稳的长文推理时再打开深度思考，日常聊天用快速模式即可。

因为模型只被允许根据可见文字推断。当证据不足时，它会把「我确定不了什么」写进「不确定性」字段，而不是编一个听起来很确定的故事。这是刻意的设计选择，也是它比「读心型」工具更安全的原因。
